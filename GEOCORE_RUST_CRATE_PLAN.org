* Purpose

Several products (agriculture, urban, environmental) share the same map canvas
behaviour that =SATELLITE_INTELLIGENCE_CANVAS_TOOLS.org= documents for the current
React + Mapbox GL app: a layered canvas (basemaps → rasters → vectors → sketch chrome →
tools), drawing / measurement / selection, a swipe comparator, remote-sensing indices with
AOI clipping, hydrology, AI-service clients, symbology, import/export and reporting.

This plan describes a *Cargo workspace* — working name =geocore= (rename freely) — that
factors that behaviour into reusable crates consumable by *Dioxus* front-ends, with these
constraints:

1. Open-source Rust only; no JavaScript libraries as functional dependencies.  The
   reference toolkits are the GeoRust ecosystem (=geo=, =geojson=, =geozero=, =geo-index=,
   =rstar=, =geotiff=, =kml=, =gpx=, =earcutr=, =geographiclib-rs=, …), =geolibre-rust=
   (opengeos: pure-Rust/WASM whitebox tools, GeoTIFF/COG, PMTiles, projections, LiDAR,
   topology), =galileo= (wgpu map renderer), =proj4rs= / =geodesy= (pure-Rust CRS).
2. Browser-first: everything compiles to =wasm32-unknown-unknown=; heavy work runs
   client-side, as in the current project.  Native (desktop / server) builds are a
   by-product, not a goal.
3. Renderer-agnostic core so the rendering backend can evolve (Galileo today, WebGPU
   later) without touching domain logic.

* Guiding architecture

** Style: layered "sans-IO" core with thin adapters (hexagonal)

Rules that keep the core portable:
- *Sans-IO*: domain crates never perform network, file or DOM access.  They expose
  "what bytes/ranges do you need" state machines (the pattern =geolibre-pmtiles= uses
  for its =Extractor=) and accept bytes back.  Adapters do the fetching.
- *Sans-render*: =geocore-map= describes the desired scene (layers, styles, order,
  camera) as data; a =MapRenderer= trait implementation applies diffs.
- *Deterministic state*: one =MapState= + =Action= enum reducer, replayable and
  unit-testable natively without a browser.  Dioxus signals wrap it.
- *Feature-gated backends* (=web=, =native=, =galileo=, =maplibre=, =whitebox=,
  =threads=) so each app pulls only what it ships.
- *Single-threaded by default on wasm*, optional =threads= feature (wasm-bindgen-rayon,
  requires COOP/COEP headers); heavy raster work goes to Web Workers via a typed
  message protocol (=postcard=) rather than shared memory.

** Why not "one big crate"
The current 29k-line page shows what happens when everything lives together.  A
workspace with small crates gives: independent compile units (wasm build times),
per-app feature selection (binary size), clear ownership, and the ability to publish
foundations (types/crs/io) separately from opinionated domain logic (eo/alerts).

* Crate-by-crate design

** geocore-types — foundations
- Geometry: re-export =geo-types= (=Point=, =LineString=, =Polygon=, =Multi*=, =Geometry=)
  wrapped in a =Geom<C: Crs>= new-type or a runtime =CrsTagged { geom, srid }= so mixing
  CRSs is a compile/runtime error, never a silent bug.
- =Feature=, =FeatureCollection= (typed properties via =serde_json::Value= or a
  =PropertyMap= with typed accessors), stable =FeatureKey= (the current
  =computeStableGisFeatureKey= behaviour).
- =Layer= descriptor (id, name, kind: Vector | Raster | Tiles | Image | Analysis, source
  provenance Upload | Api | ArcGis | Stac | Tool, visibility, opacity, order tier).
- =Aoi= (Drawn | FromLayer { layer, selected_only, filter } | Viewport), =Bbox=, =LonLat=.
- Raster descriptor: =GridSpec= (size, geo-transform, CRS, nodata), =Band= dtype enum.
- Time: =SceneDate=, =DateRange=, =TimeWindow= (use =time= crate; =web-time= on wasm).
- Units: =Length=, =Area= with unit enums (m/km/ft/mi, m²/ha/acre/km²).
- Errors: one =GeoError= per crate via =thiserror=; =no_std=-friendly where feasible.
- Traits (ports): =TileSource=, =ByteRangeSource=, =Clock=, =Rng=.

** geocore-crs — projections
- Backend: =proj4rs= (pure Rust, wasm32 target, proj4js-compatible API, EPSG via
  =crs-definitions=); optional =geodesy= for pipeline / datum-shift work.
- API: =Crs::epsg(4326)=, =Transform::new(from, to)=, =transform_geometry=,
  =transform_bbox= (densified edges), Web-Mercator helpers (=lonlat_to_mercator=,
  =mercator_bounds_for_tile=).
- WKT/PRJ ingestion for shapefiles: =proj4wkt= (3liz) → proj string.
- Geodesic distance/area: =geographiclib-rs= (Karney) with =geo= Haversine fallback.

** geocore-io — codecs (bytes in, structs out; no I/O)
| Format | Read | Write | Crates |
|--------+------+-------+--------|
| GeoJSON / TopoJSON | ✓ | ✓ | =geojson=, own TopoJSON→GeoJSON arc decoder |
| Shapefile (.zip of shp/shx/dbf/prj/cpg) | ✓ | ✓ | =shapefile=, =zip= (=deflate= only, wasm-safe), =encoding_rs= |
| KML / KMZ | ✓ | ✓ | =kml=, =zip= |
| GPX | ✓ | – | =gpx= |
| WKT / WKB / MVT / CSV / FlatGeobuf | ✓ | ✓ | =geozero= (+ =flatgeobuf=) |
| CSV / XLSX tables → points | ✓ | ✓ | =csv=, =calamine= (read), =rust_xlsxwriter= (write) |
| GeoTIFF / COG (incl. Terrain-RGB PNG) | ✓ | ✓ | =geotiff= / =tiff=, or =geolibre-wasm= =GeoTiffReader= / =CogBuilder= behind =feature = "geolibre"=; =image= for PNG/JPEG/WebP + world files (=.tfw/.pgw/.jgw/.wld=) |
| LAS / LAZ (optional) | ✓ | – | =las= (+ =laz=) |
| IFC / BIM footprint (optional) | ✓ | – | =ifc-rs= or defer; keep as an extension trait |
Design: =trait Codec { fn sniff(bytes) -> Option<Format>; fn decode(bytes, opts) -> Dataset }=;
=Dataset = Vector(FeatureCollection) | Raster(RasterImage) | Table(Rows)=.  Import metadata
(geometry kind detection, CRS guess, feature count) mirrors =siCustomLayerFactory=.

** geocore-index — spatial indexing & stores
- =geo-index= (Flatbush / KDBush, zero-copy, packed) for static layers; =rstar= for
  dynamic edits.
- =FeatureStore= (arena of features + index + attribute columns) with viewport queries
  and a =ViewportFeatureCache= for streamed ArcGIS/WFS layers.
- Attribute query engine for "definition query" / "select by attributes" (small
  expression parser → predicate).

** geocore-ops — vector analysis, measurement, selection
- =geo= algorithms: area, length, centroid, convex hull, simplify (RDP/VW), buffer,
  boolean ops (union/intersection/difference/clip), contains/intersects/within,
  =earcutr= triangulation.
- Measurement engine (ports the 12 modes): distance, area, perimeter, rectangle,
  circle, radius, bearing/azimuth, angle, coordinate, elevation, 3D distance, height —
  geodesic by default, unit conversion via =geocore-types= units.
- Selection queries: point (with overlap stack), rectangle, polygon, lasso, circle,
  line, trace; set modes New/Add/Remove/Subset; "select by location" relations
  (intersects, within, contains, overlaps, touches, within-distance, completely-contains).
- Sketch geometry helpers: circle from centre+edge with cardinal handles, rectangle
  from two corners, polygon ring closing, vertex insert/move/delete.

** geocore-raster — grids, band math, legends, hydrology
- =Raster<T>= over =ndarray= (bands × rows × cols) + =GridSpec=; typed dtypes; nodata mask.
- Band-math expression engine: parse ="(B8-B4)/(B8+B4)"= → AST → vectorised evaluation
  (also emits Sentinel Hub evalscript JS *text* for server-side WMS — generating text is
  not "using JavaScript").
- Reclass, thresholds, histograms, percentile stretch, class-area statistics (the
  Layer-Live legend analyze), zonal statistics over =Aoi= (rasterise with
  =geo-rasterize=).
- Colour ramps & legends: =colorous= ramps + own 10-class agri ramps; =Legend= spec output.
- Contours: =contour= crate (marching squares) and isobands.
- Hydrology & terrain: slope, aspect, hillshade, TPI/TRI/TWI, D8 flow direction, flow
  accumulation, Strahler/Shreve streams, watershed/basins.  Two implementations behind
  features: =native-hydro= (own small D8 kernels, good for AOI-scale DEMs) and
  =whitebox= (delegate to =whitebox-wasm= / =geolibre-tools= =wbcore::Tool= registry —
  hundreds of vetted tools, runs in a worker).
- Terrain-RGB decode/encode (Esri/Mapbox formula) for the DEM proxy tiles.
- Raster georeferencing: GCP affine / polynomial solve (=nalgebra=), world-file emit.

** geocore-tiles — tile math & tiled sources
- XYZ/TMS/quadkey math, WebMercator bounds, max-native-zoom per provider (port of
  =rasterTileZoom=).
- URL builders: XYZ templates, WMS GetMap (incl. =GEOMETRY= WKT clip, =EVALSCRIPT=
  base64, =TIME=, =MAXCC=), WMTS, ArcGIS MapServer/ImageServer export tiles.
- PMTiles: =geolibre-pmtiles= (sans-IO extractor + tile math) or =pmtiles= crate; MVT
  decode via =geozero= (=mvt= feature) — replaces the current hand-rolled
  =@mapbox/vector-tile= + =pbf= FTW loader.
- STAC: =stac= crate types + sans-IO search request builder / response parser
  (Planetary Computer, CDSE).
- Basemap catalog as data (the 21 entries from the report) with attribution and
  fallback rules (401/403 → Esri World Imagery).

** geocore-eo — remote-sensing domain logic
- Index catalog as data: core S2 indices, agro composites (+Δ), mangrove, per-collection
  (S3/S5P/S6/CCM/DEM/CLMS), ASTER, CHIRPS analytics — each with formula AST, bands,
  default ramp, legend classes, time window (30/45/60/90/120 d) and provider profile.
- Provider registry (Sentinel Hub, CDSE, Landsat/HLS, ASTER, commercial VHR placeholders)
  with layer-profile filtering.
- Scene resolution: latest / nearest / previous scene from STAC results with cloud
  filter and cache policy (pure functions over STAC items).
- AOI clip planning: chunking of a multipolygon into WMS =GEOMETRY= strings under URL
  budget (port of =siSentinelAoiWmsStack= / =sentinelHubWmsAoiClip=), producing
  =ClippedTileStack { chunks: [(bounds, url)] }= consumed by =geocore-map=.
- Time-series analytics (zonal series, smoothing, anomalies, phenology metrics),
  LULC composition.
- Rule engines: crop alerts (ΔCHAS), WAPI/ISS irrigation stress, stress zones, flood
  thresholding (SAR dB) — pure, testable with fixtures.

** geocore-symbology — cartography model
- =SymbologyStyle= (single, unique, graduated colour, size, colour+size, dot density,
  threshold markers), =ClassMethod= (Jenks natural breaks, quantile, equal interval),
  =ColorRamp= (viridis/blues/greens/plasma/magma/turbo + custom), stroke/fill styles,
  point symbol gallery.
- Label style (field, font stack, halo, min/max zoom), popup config, legend spec.
- ArcGIS =drawingInfo= renderer → =SymbologyStyle= converter (keep ArcGIS Online looks).
- Converters: =SymbologyStyle= → Galileo style; → MapLibre style JSON (for the interim
  backend and for exporting styles).

** geocore-map — the renderer-agnostic map state machine (the heart)
- =MapState=: camera (=Viewport=: lon/lat/zoom/bearing/pitch, 2D/3D flag, globe flag),
  =LayerStack=, active =Aoi=, =SelectionState=, =DrawState=, =MeasureState=,
  =SwipeState=, =Timeline=, =IdentifyState=, undo/redo history.
- =Action= enum (=SetBasemap=, =AddLayer=, =ReorderLayer=, =ToggleVisibility=,
  =SetOpacity=, =StartDraw(tool)=, =AddVertex=, =CommitSketch=, =MeasureMode(..)=,
  =Select { tool, set_mode, geometry }=, =SwipeSet { mode, before, after, split }=,
  =TimelineStep=, …) → =fn reduce(&mut MapState, Action) -> Vec<Effect>=.
- =Effect= = things adapters must do (fetch tiles, run worker job, emit renderer diff).
- *Z-order policy* as an explicit tier table that reproduces Part I of the report:
  =Terrain → Basemap → AoiFillUnderRaster → AnalysisRaster → ImportedVector →
  ToolResultVector → AoiOutline → SelectionHighlight → SketchChrome=; every layer
  declares its tier; the policy is enforced in one place (no more scattered
  =moveLayer= calls).
- Flicker-free raster swap: the ping-pong double-source strategy modelled as a
  =RasterSlotPair= state machine (load hidden slot → swap opacity on ready).
- Swipe: =SwipeState { mode: Dates | Layers | Both, before, after, split }= producing two
  layer descriptors; renderer adapters implement the clip (Galileo: scissor rect /
  second view; MapLibre interim: second map + CSS clip-path).
- Interaction adapters: pointer events normalised (=PointerAction=) so Dioxus and tests
  feed the same reducer.

** geocore-render — renderer port
#+BEGIN_SRC rust
pub trait MapRenderer {
    fn mount(&mut self, canvas: CanvasHandle, opts: RendererOptions) -> Result<(), RenderError>;
    fn apply(&mut self, diff: SceneDiff);             // add/remove/reorder layers, paint updates
    fn set_camera(&mut self, cam: &Camera, anim: Animation);
    fn project(&self, lonlat: LonLat) -> ScreenPt;      // for HTML markers / popups
    fn unproject(&self, pt: ScreenPt) -> LonLat;
    fn query_features(&self, pt: ScreenPt, radius_px: f32) -> Vec<FeatureHit>;
    fn snapshot_png(&self) -> Result<Vec<u8>, RenderError>;
}
#+END_SRC
=SceneDiff= is computed by =geocore-map= from two =LayerStack= snapshots (like React's
reconciliation but explicit), so backends stay thin.

** geocore-render-galileo — primary backend (pure Rust)
- =galileo= 0.2.x: raster tile layers, vector tile layers with styling, feature layers,
  3D view/objects, wgpu → WebGL2/WebGPU; roadmap v0.3 adds globe/terrain.
- Mapping: =Basemap= → =RasterTileLayer=; imported vectors → =FeatureLayer= with
  =geocore-symbology= styles; analysis rasters/images → image layers; PMTiles/MVT →
  vector tile layer; markers/popups → DOM elements positioned via =project()=.
- Gaps to track: globe projection & terrain (interim via MapLibre backend), label
  collision, heatmap/cluster styles (roadmap v0.4).

** geocore-render-maplibre — interim backend (JS interop, not JS logic)
- Thin =wasm-bindgen= bindings to MapLibre GL JS *only as a rendering device* (globe,
  terrain, hillshade, labels) while Galileo matures.  All logic stays in Rust; the JS
  surface is a handful of =addSource/addLayer/moveLayer/setPaintProperty= calls.
  Feature-gated; deletable later without touching domain crates.

** geocore-net / geocore-workers — platform adapters
- HTTP: =gloo-net= on web (=fetch=, Range headers for COG/PMTiles), =reqwest= on native;
  token providers (Sentinel Hub, ArcGIS portal, API keys) as a =Credentials= trait.
- Cache: in-memory LRU (=lru=), IndexedDB (=idb= / =gloo-storage=) for tiles, scene
  lists, saved maps, user prefs (replaces =localStorage= sprawl).
- Workers: =gloo-worker= typed bridge; job kinds: decode raster, band math, hydrology,
  contour, shapefile parse, report build.  Optional =wasm-bindgen-rayon= when the host
  can set COOP/COEP.

** geocore-ai — ML service clients (typed, transport-agnostic)
- Request/response types + endpoint builders for the existing Python services: SAM,
  SAM2 refine, SegFormer, temporal transformer, tree detection, field boundary
  (AFD/FTW/Delineate-Anything, SEN2SR), image classification, GeoAI chat; plus LLM
  provider adapters (Gemini, Claude, DeepSeek, Ollama) as plain HTTP JSON.
- Post-processing that belongs client-side: mask PNG → polygons (=geocore-raster=
  vectorise), clip results to AOI, class styling, export packs.
- Optional on-device inference behind =feature = "ondevice"= via =tract= or =candle=
  (ONNX in wasm) for small models (e.g. tree crowns fallback).

** geocore-report — exports
- Vector: GeoJSON, Shapefile zip, KML/KMZ, CSV, XLSX (=rust_xlsxwriter=), GPKG (via
  =geozero= WKB + =rusqlite= — native only; wasm via =sql.js=-free =sqlite-wasm-rs= is
  optional).
- Raster: GeoTIFF (Float32 index + RGB + world files), PNG snapshots.
- Documents: DOCX (=docx-rs=), PDF (=printpdf= / =genpdf=), charts rendered with
  =plotters= (canvas backend on web, bitmap on native) — mirrors the 14 time-series export
  kinds.

** geocore-dioxus — UI kit (Dioxus 0.7)
- =MapView= component: mounts a =<canvas>= via =onmounted=, owns the renderer, wires
  pointer/keyboard events to =Action=s; exposes =use_map()= (signals for =MapState=
  slices) and =use_map_effects()= (drives =geocore-net= / =geocore-workers=).
- Components mirroring the current chrome: =LayerList= (TOC with tier-aware ordering),
  =BasemapGallery=, =DrawToolbar=, =MeasurePanel=, =SelectionWorkbench=, =SwipeControl=,
  =TimelineBar=, =LegendPanel=, =GoToXy=, =SearchBox=, =SymbologyStudio=,
  =LabelingPanel=, =PopupConfigurator=, =FeaturePopup= (positioned via =project()=),
  =RemoteSensingPanel=, =HydroPanel=, =AlertCenter=, =ReportExportMenu=.
- Headless first: each component takes state + emits =Action=; styling via CSS classes
  (Tailwind-compatible) so apps can re-skin.

** geocore-wasm — JS facade (migration path)
- =wasm-bindgen= exports for the existing React app: codecs, CRS, measurement, index
  catalog, AOI clip planning, z-order policy.  Lets the current product adopt the Rust
  core incrementally while the Dioxus apps are built.

* WASM-in-the-browser engineering notes

- Target =wasm32-unknown-unknown=; build with =dx= (Dioxus CLI) for apps, =wasm-pack=
  for =geocore-wasm=; post-process with =wasm-opt -O3=; enable =+simd128= for raster
  kernels.
- Async: =wasm-bindgen-futures= + =futures=; no =tokio= runtime in core crates (use
  =async-trait=-free =impl Future= APIs; adapters pick the executor).
- Time & randomness: =web-time=, =getrandom= with =js= feature; =fastrand= for non-crypto.
- Memory: keep rasters in typed =Vec<f32>=/=u8=; move big buffers to workers with
  =Transferable= =ArrayBuffer=; cap textures (8192 px) as today.
- Binary size: split heavy optional tools (=whitebox=, =las=, =docx=, =printpdf=) behind
  features and, for the demo app, load them as a *separate worker wasm* so the main
  bundle stays small.
- Interop boundary: only =geocore-render-maplibre= and =geocore-dioxus= touch
  =web-sys=/=js-sys=; everything else must compile with =--target wasm32= *and* natively.

  =Cross-Origin-Opener-Policy: same-origin= and =Cross-Origin-Embedder-Policy: require-corp=.
- Storage: IndexedDB for tile/scene caches and saved maps; OPFS for large local
  rasters when available.

* Key decisions & risks

| Decision | Choice | Risk / mitigation |
|----------+--------+-------------------|
| Renderer | Galileo primary; MapLibre interim behind a trait | Galileo lacks globe/terrain/labels today; the =MapRenderer= port isolates it; revisit when v0.3 lands |
| Projections | =proj4rs= (+ =geodesy= optional) | Not full PROJ; sufficient for EPSG:4326/3857/UTM/LCC; WKT via =proj4wkt= |
| Hydrology | own D8 kernels + optional =whitebox-wasm= | whitebox wasm is large → worker + lazy load |
| GeoTIFF | =geotiff=/=tiff= vs =geolibre-wasm= reader | choose per feature; COG streaming needs Range → sans-IO reader |
| Formats without mature Rust | IFC, GPKG in browser, LAZ | keep behind optional features / native-only; document gaps |
| Threads in browser | opt-in only | COOP/COEP hosting requirement |
| State model | single reducer | discipline needed to keep effects out of the core; enforce with =#![forbid(unsafe_code)]= and no =web-sys= dep in core crates |

* Appendix B — core trait sketches

#+BEGIN_SRC rust
/// Sans-IO byte-range consumer (COG, PMTiles, FlatGeobuf).
pub trait RangeReader {
    fn wanted(&self) -> Vec<ByteRange>;
    fn feed(&mut self, offset: u64, bytes: &[u8]) -> Result<(), IoError>;
    fn is_done(&self) -> bool;
}

/// A tiled source the map can draw (XYZ, WMS-as-tiles, PMTiles, in-memory image pyramid).
pub trait TileSource {
    fn scheme(&self) -> TileScheme;                 // XYZ / TMS / WMS / PMTiles
    fn url_for(&self, z: u8, x: u32, y: u32) -> Option<String>;
    fn bounds(&self) -> Option<Bbox>;
    fn max_native_zoom(&self) -> Option<u8>;
}

/// Everything a UI can do to the map; the only mutation path.
pub enum Action {
    Camera(CameraAction),
    Basemap(BasemapId),
    Layer(LayerAction),          // add / remove / reorder / visibility / opacity / style
    Aoi(AoiAction),              // set drawn / from-layer / clear
    Draw(DrawAction),            // start(tool) / vertex / undo / commit / cancel
    Measure(MeasureAction),
    Select(SelectAction),
    Swipe(SwipeAction),
    Timeline(TimelineAction),
    Identify(IdentifyAction),
}

/// Side-effects the reducer asks adapters to perform.
pub enum Effect {
    RenderDiff(SceneDiff),
    Fetch { req: HttpRequest, on_done: EffectId },
    RunJob { job: WorkerJob, on_done: EffectId },
    Persist { key: String, bytes: Vec<u8> },
}

pub fn reduce(state: &mut MapState, action: Action) -> Vec<Effect>;
