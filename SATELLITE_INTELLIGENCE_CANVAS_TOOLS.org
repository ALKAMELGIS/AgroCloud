* Scope and method

This report inventories every tool, layer class and utility that participates in the
*Satellite Intelligence* map canvas (route =/satellite=, page component
=frontend/src/pages/satellite/SatelliteIntelligence.tsx=, ~29k lines) and the panels
mounted around it.  It was produced by static reading of the source tree only — no
environment was created, no dependencies installed, nothing executed.

The canvas is a single *Mapbox GL JS* map (=react-map-gl/mapbox= =<MapGL>=, globe
projection).  Part I walks the render stack from the bottom-most pixel (terrain mesh and
basemap rasters) to the top-most DOM overlay (toolbox chrome, swipe handle, remote-sensing
panels).  Part II catalogues each tool family in detail.  Part III lists libraries,
backend services and a file index.

Conventions:
- =monospace= → Mapbox source/layer id, TypeScript symbol or file path.
- Paths are relative to =frontend/src/= unless they begin with =backend/= or =services/=.
- "SI" = Satellite Intelligence.

* PART I — Canvas stack, bottom to top

The stack below is the *effective* draw order.  Some tiers are declared as React
=<Source>/<Layer>= children of =<MapGL>=; others are added imperatively
(=map.addSource/addLayer=) and then re-ordered by two z-order utilities:

- =lib/siCustomLayerZOrder.ts= — =siParkBasemapRastersBelowOverlays()= slides every
  basemap raster immediately under the first non-basemap layer;
  =siRaiseCustomLayersAboveBasemap()= raises imported GIS overlays
  (=-fill/-line/-circle/-marker/-arcgis-icon/-cluster/-cluster-count/-raster/-arcgis-raster/-label=,
  =-vt-*=, =-arcgis-*=) above them and keeps sketch chrome on top.
- =lib/siMapAnalysisLayerOrder.ts= — =syncSiMapAnalysisLayerOrder()= enforces
  *basemap → AOI fill → analysis raster → vector outlines → draft sketch → MCDA*.
- Both are invoked from =raiseOverlaysThenAnalysisOrder()= (SI page, ~L19524) on
  =onStyleData=, after custom-layer paint, and when the Layers-AOI raster stack is
  (re)mounted.
